# Roll The Bones: Art Spec Guide

This guide lists every piece of 2D art the game needs, with the technical specs each asset must meet to drop straight into the Godot project.

It covers the UI chrome and icons, dice, characters, items, skills, the world map, the dungeon and the combat scene. It does not cover VFX: the particle and sprite-sheet effects use a third-party kit that stays as it is.

### Row format

Every asset row has these columns:

| Column | Meaning |
|---|---|
| **Asset ID** | Stable ID to quote in invoices, feedback and file names (e.g. `UI-PNL-01`, `ENM-navy-trash-drum_major`) |
| **Deliver as** | The exact path and file name to deliver, relative to the project root |
| **On-screen** | The largest size the asset is ever displayed at, in game pixels |
| **Source** | The pixel size to deliver |
| **9-slice L/T/R/B** | For stretchable art: the corner and border widths in source pixels (see [9-slice rules](#9-slice-rules)) |
| **States** | Separate files needed for each interaction state or variant |
| **Tint** | ✔ means the art must be **white or greyscale on transparent**, because the game colours it at runtime |
| **Priority** | Delivery order, see [Priority](#priority) |
| **Status** | NEW (nothing exists yet), REDO (a placeholder exists), REVIEW (existing art that may be kept), NEEDS HOOKUP (the game has a slot for it but doesn't draw it yet; see the appendix) |

## Global technical standards

### Screen and resolution
- The game renders at a fixed **1080 × 1920 portrait** resolution (stretch mode `viewport`, aspect `expand`) and then scales the whole frame to fit the device. **1 game pixel = 1 pixel at 1080p.** Wider or taller phones show extra space at the edges; nothing is re-laid out.
- So **the on-screen size is the maximum useful resolution.** Delivering above it only helps where art is zoomed (the world map) or reused at several sizes. That is why a Source size can be larger than the On-screen size.
- **Keep layered masters at 2×** of the delivered size (PSD, Procreate, Krita or SVG). If the project later moves to a higher-resolution render mode, the 2× versions will be requested.

### File format
- **PNG, 32-bit RGBA, sRGB, straight (non-premultiplied) alpha.** No embedded colour profile other than sRGB.
- Transparent pixels must have no coloured fringe. Bleed the edge colour outward under the transparency, or use export settings that prevent halos.
- **Icons:** keep the art inside a **safe area of 90% of the canvas**, centred, with transparent padding. Don't trim icons to their content; every icon in a set shares the same canvas size.
- **Standard sizes** (use the exact size a row specifies):

| Use | Source size |
|---|---|
| Inline and badge icons | 64 × 64 |
| Status, element, stat and currency icons | 128 × 128 |
| Skill, action, navigation and category icons | 256 × 256 |
| Equipment and consumable icons | 360 × 360 (matches the existing item art) |
| Map-radial category icons | 256 × 256 |
| Enemy portraits | 512 × 512 |
| Companion portraits | 256 × 256 |
| Dialogue busts | 400 × 640 (drawn at native pixel size, see `04_characters.md`) |
| Player bust (HUD portrait) | 720 × 720 |
| Map backgrounds | 3840 × 3840 (zoomable) |

### Tintable art (Tint ✔)
Some art is coloured by the game: die bodies (by element), action-field cards (by element), progress-bar fills (by resource), and the rarity glow drawn around icons. For these:
- Paint in **white or neutral greyscale** on transparent. The game multiplies it by a colour, so white becomes the tint colour and black stays black.
- Keep shading in value only, with no hue. Where a highlight should stay white after tinting, supply it as a **separate overlay file** (the row says so).
- **Don't paint rarity borders or frames on item icons.** Rarity is drawn by a shader outline around the icon's alpha, so a clean silhouette edge matters more than a frame.

### 9-slice rules
A 9-slice (Godot `StyleBoxTexture` or `NinePatchRect`) splits an image into corners, edges and a centre. It draws the corners at their real size, stretches the edges along one axis, and stretches the centre in both.
- **Godot draws the margins at source-pixel size and does not scale them down.** A 70 px corner in the file is a 70 px corner on screen. So **9-slice art is delivered at 1× on-screen scale**, unlike icons.
- Corners hold all the ornament. Edges must be **uniform along their length** (they stretch, not tile). The centre must be flat or a very soft, stretch-safe texture.
- Mark the margins on a guide layer in the master file, and state the values L/T/R/B in pixels on delivery.
- **Content margin** is the padding between the frame and the content inside it. The row gives it where it matters; otherwise the default is the border width plus 8 px.
- Minimum drawable size is L+R wide and T+B tall. Rows state the smallest size the panel is used at, so the corners must fit it.

### Button and toggle states
- Every button needs **one file per state**: `normal`, `hover`, `pressed`, `disabled`. `focus` is an **outline overlay only** (drawn on top for gamepad or keyboard focus).
- **Toggle buttons** (tabs, filters, category bars) also need `selected` and `selected_pressed`. The current tabs have no selected state, which is a known usability gap.
- `hover` exists for desktop and web builds. Keep it subtle; on mobile it's never seen.
- Keep all states pixel-aligned on the same canvas size. Pressed usually shifts content 2–4 px down, and that shift is baked into the art.

### Naming and folders
- `snake_case` only: letters, digits and underscores. **No spaces, apostrophes or capitals.** Several existing files break this and are being renamed.
- Pattern: `{category}_{name}[_{variant}][_{state}].png`, e.g. `btn_primary_pressed.png`, `panel_modal.png`, `status_burn.png`.
- Deliver into folders that mirror the **Deliver as** path, e.g. a zip whose root contains `assets/ui/buttons/...`.

### Colour
The UI palette is **Endesga-64** (see `PALETTE` in `scripts/ui/theme_manager.gd`). The runtime colours below are fixed and applied by code, so art that sits next to them must read well against them:

| Group | Colours |
|---|---|
| Elements | fire `#ff5000`, ice `#0cf1ff`, shock `#0069aa`, poison `#5ac54f`, shadow `#622461`, slashing `#b4b4b4`, blunt `#bf6f4a`, piercing `#f6ca9f` |
| Rarity | common `#b4b4b4`, uncommon `#5ac54f`, rare `#0098dc`, epic `#ca52c9`, legendary `#ffa214` |
| Bars | health `#5ac54f`, health low `#c42430`, mana `#0069aa`, xp `#ca52c9`, armor `#858585`, barrier `#0098dc` |
| Surfaces | darkest `#0e071b`, dark `#1a1932`, panel `#2a2f4e`, elevated `#424c6e`; borders `#657392` / `#92a1b9` |
| Text | primary `#ffffff`, secondary `#c7cfdd`, muted `#92a1b9` |

Whether the UI chrome keeps this palette or gets a new one is an open question in `00_style_direction.md`.

### Fonts
Current fonts are **Stoke** (UI and headings) and **Oregano** (flavour text). Fonts are not an art deliverable, but the chrome must leave room for text at these sizes: body 30–40 px, headers 48–60 px, floaters up to 100 px with a thick outline.

## Priority

| Priority | Meaning | Scope |
|---|---|---|
| **P0** | Vertical slice: the minimum for a presentable demo | Core UI kit, dice, combat HUD, player bust, Sanctum Navy trash and elite portraits, status icons used in the demo |
| **P1** | Core content | All item, skill and status icons, companions and NPCs, map and dungeon basics |
| **P2** | Full content | Remaining navy enemies, consumables, player action icons, events, shrines, run affixes |
| **P3** | Nice to have, test content, or awaiting code | Extra NPC moods, enemy action icons, baseline test enemies, decor extras |

## Delivery checklist (per batch)
1. Files match the **Deliver as** paths and names exactly.
2. Each file has the right pixel size, is RGBA, and has no halo fringe.
3. 9-slice files come with their L/T/R/B values (on the invoice or in a `margins.txt`).
4. Every state exists for each button or toggle.
5. Tintable files are greyscale.
6. Icons in a set share one canvas size and one safe area.
7. Layered masters are uploaded to the shared drive.
8. The batch list quotes the Asset IDs it delivers.

## Out of scope
- **VFX** (particles, cast, projectile and impact sheets, status loops): uses the third-party kit.
- **Future content**: the Warrior class and its trees, the FAITH element, regions 2–6.
- **Legacy corridor dungeon view**: wall, door and floor textures in `DungeonDefinition` that are no longer rendered.
- **Enemy full-body sprites** (`EnemyData.sprite_texture`) and **companion idle animations** (`CompanionData.idle_animation`): no current layout draws them.
- **Affix and dice-affix icons** (`Affix.icon`, `DiceAffix.icon`, 300+ affixes): affixes are shown as text, and there's no plan to iconise them.
- **VFX-related textures** (`AffixRollVisual.projectile_texture`, the emanate and summon preset textures): part of the VFX kit.
- **Fonts, audio, animation rigs.**
